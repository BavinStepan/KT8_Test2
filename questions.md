# Ответы на контрольные вопросы

1. Для чего предназначены модульные тесты?
Чтобы автоматически проверять, что отдельные части кода работают правильно. Они быстро
показывают, что сломалось после изменений, не дают вернуться старым ошибкам и заодно
описывают, как код должен себя вести.

2. Чем отличается NUnit от xUnit?
Синтаксисом и подготовкой теста. В NUnit тесты помечаются [Test], данные передаются через
[TestCase], а подготовка и уборка делаются в [SetUp] и [TearDown]. В xUnit тесты - это [Fact],
параметризованные - [Theory] с [InlineData], а подготовка идёт в конструкторе класса и Dispose,
потому что xUnit создаёт новый экземпляр класса на каждый тест. Ещё xUnit по умолчанию
запускает часть тестов параллельно, а NUnit - последовательно.

3. Что такое параметризация тестов?
Это когда один тестовый метод запускается много раз с разными данными. Вместо десяти почти
одинаковых тестов пишется один, а данные перечисляются отдельно: [TestCase] в NUnit,
[Theory] с [InlineData] в xUnit, parametrize в pytest.

4. Для чего используются фикстуры?
Чтобы подготовить окружение перед тестом и убрать за собой после. Например, создать клиент
или тестовые данные, а потом удалить их. В NUnit это [SetUp] и [TearDown], в xUnit -
конструктор и Dispose, а для общих данных на весь класс - IClassFixture.

5. Зачем тестировать работу репозиториев?
Чтобы отдельно проверить слой работы с базой данных: правильные ли запросы, правильно ли
сущности превращаются в таблицы, что будет, если записи нет. Моками такие ошибки не поймать,
они видны только на реальной или тестовой базе.

6. Как выполняется запуск тестов в .NET? (работаю в Visual Studio 2022)
Через Test Explorer (Ctrl+E, T): Run All или правый клик по проекту и Run. Из консоли —
dotnet test в папке решения, можно указать конкретный проект. Ещё есть Ctrl+R, A для запуска
всех тестов и Ctrl+R, T для тестов в текущем месте.

7. Что общего между pytest и xUnit?
Оба сами находят тесты, умеют параметризацию, дают способ подготовить и убрать окружение
(фикстуры в pytest, конструктор и Dispose в xUnit), имеют набор проверок и возвращают код
завершения, по которому понятно, прошли тесты или нет. Задача одна, отличается только запись.

8. В чем преимущества pytest?
Мало лишнего кода: тест - обычная функция с assert, классы и атрибуты не нужны. Удобные
фикстуры с очисткой через yield, простая параметризация, понятный вывод при падении и много
плагинов (pytest-asyncio, pytest-cov, pytest-xdist).

9. Для каких задач может быть интересен Expecto?
Это фреймворк для F#. Он удобен в F#-проектах: тесты описываются как список значений, их можно
собирать и фильтровать кодом, есть property-based тестирование через FsCheck. Хорошо подходит
для библиотек на F#, где атрибутные фреймворки выглядят чужеродно.
